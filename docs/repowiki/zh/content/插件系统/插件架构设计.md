## 项目结构

baozi项目的插件系统采用前后端分离的设计模式，插件目录位于根目录下的`plugins/`文件夹中。每个插件都有独立的子目录，包含前端、后端和共享代码三个主要部分。

```mermaid
graph TD
A[plugins/] --> B[插件名称/]
B --> C[client/]
B --> D[server/]
B --> E[shared/]
B --> F[plugin.json]
C --> G[index.tsx]
C --> H[组件文件]
D --> I[index.ts]
D --> J[API路由]
D --> K[任务处理器]
E --> L[工具函数]
```

## 核心组件

插件系统的核心是`PluginManager`类，它在前后端分别实现了插件的注册、管理和调用机制。前端插件管理器位于`app/utils/PluginManager.ts`，后端插件管理器位于`server/utils/PluginManager.ts`。

```mermaid

+type : Hook
+name : string
+description : string
+value : any
+priority : number
+deployments : string[]
}

```

## 插件加载与初始化流程

插件系统的加载流程分为前端和后端两个独立的路径，确保前后端插件的隔离性和安全性。

```mermaid
sequenceDiagram
participant Client as "前端应用"
participant Server as "后端服务"
participant PluginManager as "PluginManager"
Client->>PluginManager : 调用loadPlugins()
PluginManager->>PluginManager : 使用import.meta.glob扫描插件
PluginManager->>Client : 动态导入所有client/index.tsx
PluginManager->>Client : 注册插件到管理器
Server->>PluginManager : 调用loadPlugins()
PluginManager->>PluginManager : 使用glob.sync扫描插件
PluginManager->>Server : require所有server/*.ts文件
PluginManager->>Server : 注册插件到管理器
```

## 插件配置文件规范

每个插件都必须包含一个`plugin.json`配置文件，定义插件的基本信息和元数据。

### 配置文件字段定义

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| id | string | 是 | 插件的唯一标识符 |
| name | string | 是 | 插件的显示名称 |
| priority | number | 否 | 插件优先级，数值越小优先级越高 |
| description | string | 否 | 插件的简要描述 |
| deployments | array | 否 | 插件支持的部署环境 |
