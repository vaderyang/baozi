- `tsconfig.json`：TypeScript编译配置文件

这些配置文件共同构成了项目的编码规范基础，确保代码质量和国际化支持的一致性。

## TypeScript配置

### 严格模式设置

项目在`tsconfig.json`中启用了多项严格模式选项，以确保代码质量和类型安全：

- `alwaysStrict`: 强制使用严格模式编译
- `noImplicitAny`: 禁止隐式的any类型
- `noImplicitReturns`: 确保函数所有路径都有返回值
- `strictNullChecks`: 启用严格的null和undefined检查
- `noErrorTruncation`: 禁止错误信息截断

这些设置有助于在编译时捕获潜在的类型错误，提高代码的可靠性和可维护性。

### 模块解析规则

项目配置了明确的模块解析规则：

- `moduleResolution`: 使用"node"模式进行模块解析
- `baseUrl`: 设置为项目根目录"."
- `paths`: 定义了路径别名映射

### 路径别名使用

项目通过`paths`配置定义了以下路径别名：

- `@server/*`: 映射到`./server/*`目录
- `@shared/*`: 映射到`./shared/*`目录  
- `~/*`: 映射到`./app/*`目录

这些别名简化了模块导入路径，提高了代码的可读性和可维护性。例如，可以使用`import User from "@shared/models/User"`而不是相对路径导入。

## 代码预提交检查

### 预提交流程

`lint-staged.config.mjs`文件定义了代码预提交时的检查流程，确保代码质量和一致性。

### 执行顺序

预提交检查按照以下顺序执行：

1. **Prettier格式化**: 首先使用Prettier对代码进行格式化
2. **oxlint静态分析**: 然后进行静态代码分析
3. **自动化翻译更新**: 最后更新国际化翻译文件

### 具体配置

对于JavaScript和TypeScript文件(`**/*.[tj]s?(x)`)，预提交检查执行以下操作：

- 运行`prettier --write`进行代码格式化
- 根据文件数量决定使用`oxlint`单个文件检查或`yarn lint --fix`批量检查
- 执行`yarn build:i18n`更新翻译文件
- 将更新的翻译文件添加到git暂存区

此外，对于`yarn.lock`和`package.json`文件，会自动执行`yarn yarn-deduplicate`来去重依赖包。

## 国际化支持

### 国际化键值提取

`i18next-parser.config.js`文件定义了国际化键值的提取规则，确保多语言支持的准确性和一致性。

### 词法分析器配置

配置文件为不同文件类型指定了相应的词法分析器：

- `.js`, `.jsx`, `.tsx`: 使用`JsxLexer`
- `.ts`: 使用`JavascriptLexer`
- `.html`, `.htm`: 使用`HTMLLexer`
- `.hbs`, `.handlebars`: 使用`HandlebarsLexer`

这种配置确保了不同类型的文件都能正确提取国际化键值。

### 命名空间分隔符

项目使用冒号(`:`)作为命名空间分隔符：

```javascript
namespaceSeparator: ":"
```

这允许使用如`t('common:button.save')`这样的语法来组织翻译键，提高键值的可读性和组织性。

### 输出文件路径

国际化键值提取后输出到以下路径：

```javascript
output: "shared/i18n/locales/en_US/translation.json"
```

此配置将所有提取的键值存储在共享目录的英文语言包中，作为其他语言翻译的基础。

### 其他关键配置

- `keySeparator`: 设置为`false`，允许使用包含点号的纯英文键
- `defaultNamespace`: 默认命名空间为"translation"
- `contextSeparator`: 上下文分隔符为下划线("_")
- `createOldCatalogs`: 不保存旧的翻译文件
- `keepRemoved`: 不保留已从代码中移除的键

## 操作指南

### 代码格式化

项目使用Prettier进行代码格式化，遵循以下规则：

- 打印宽度: 80字符
- 尾随逗号: 使用ES5风格

这些规则在`.prettierrc`文件中定义，确保团队成员使用一致的代码风格。

### 类型检查

TypeScript编译器配置了严格的类型检查选项，开发人员应：

1. 确保所有变量都有明确的类型声明
2. 避免使用`any`类型
3. 正确处理null和undefined值
4. 确保函数所有路径都有返回值

### 国际化文本提取

提取国际化文本的步骤：

1. 在代码中使用`t()`函数标记需要翻译的文本
2. 提交代码时，预提交钩子会自动提取新键值
3. 检查生成的`translation.json`文件，确保所有键值正确提取
4. 将新的英文键值翻译成其他支持的语言

## 常见问题

### 类型错误

当遇到类型错误时，应：

1. 检查变量类型声明是否正确
2. 确认函数参数和返回值类型匹配
3. 使用类型断言时要谨慎
4. 必要时添加类型注解

### 格式化问题

如果代码格式化出现问题：

1. 确保Prettier版本一致
2. 检查`.prettierrc`配置是否正确加载
3. 确认编辑器配置与项目要求一致

### 国际化键值未提取

如果国际化键值未被正确提取：

1. 检查是否使用了`t()`函数包裹文本
2. 确认文件类型是否在`i18next-parser.config.js`的词法分析器配置中
3. 检查`input`配置是否包含相关文件路径
4. 验证预提交钩子是否正常执行
