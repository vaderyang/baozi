## API密钥模型安全设计

API密钥模型（ApiKey）采用了多层安全机制来保护密钥数据。核心安全设计包括对secret字段的废弃标记、hash字段的唯一性约束以及@SkipChangeset装饰器的使用。

在模型定义中，`secret`字段已被标记为`@deprecated`，表示该字段即将被移除。这一设计决策是为了避免在数据库中存储明文密钥，从而降低安全风险。同时，`hash`字段被设置为唯一约束（`@Unique`），确保每个API密钥的哈希值在系统中是唯一的，防止重复密钥的生成。

`@SkipChangeset`装饰器被应用于`hash`、`last4`和`lastActiveAt`字段。该装饰器的作用是跳过变更集（changeset）的跟踪，这意味着这些字段的更改不会被记录在变更历史中。这种设计可以防止敏感信息（如密钥的最后四位字符和最后活动时间）被意外暴露在变更日志中。

## Sequelize钩子函数工作机制

### generateSecret钩子

`generateSecret`是一个在验证前（`@BeforeValidate`）触发的静态方法。当创建新的API密钥时，如果`hash`字段为空，该钩子会生成一个包含前缀`ol_api_`和38位随机字符串的密钥。生成的密钥会被存储在`value`虚拟字段中，并通过`hash`函数计算其哈希值，然后将结果存储在`hash`字段中。这一过程确保了明文密钥不会直接存储在数据库中，而是以哈希形式保存。

### updateLast4钩子

`updateLast4`是一个在保存前（`@BeforeSave`）触发的静态方法。该钩子负责提取密钥的最后四位字符并存储在`last4`字段中。它会优先使用`value`字段的值（如果存在），否则使用`secret`字段的值。提取的最后四位字符用于在用户界面中显示密钥的预览，而不会暴露完整的密钥。

### findByToken静态方法

`findByToken`静态方法用于通过提供的输入字符串查找API密钥。该方法使用`Op.or`操作符在`secret`和`hash`字段中进行搜索。搜索时，它会先尝试匹配明文密钥，如果未找到，则计算输入字符串的哈希值并进行匹配。这种方法既支持旧的明文密钥查找，又兼容新的哈希密钥查找，实现了平滑的迁移。

## 哈希函数实现细节

`crypto.ts`文件中的`hash`函数使用Node.js内置的`crypto`模块实现SHA-256哈希算法。该函数接收一个输入字符串，创建一个SHA-256哈希对象，更新其内容为输入字符串，然后以十六进制格式输出哈希值。SHA-256是一种安全的加密哈希函数，能够将任意长度的输入转换为固定长度的256位哈希值，具有良好的抗碰撞性和单向性。

安全考量方面，使用SHA-256哈希算法可以有效防止密钥的逆向工程。即使攻击者获取了哈希值，也无法轻易推导出原始密钥。此外，系统还实现了`safEqual`函数，使用`crypto.timingSafeEqual`进行常量时间比较，防止时序攻击。这种设计确保了密钥验证过程的安全性，避免了通过测量响应时间来推断密钥信息的可能性。

## 安全审计建议与潜在风险

### 安全审计建议

1. **定期审查密钥使用情况**：监控`lastActiveAt`字段，识别长时间未使用的密钥并建议用户撤销。
2. **实施密钥轮换策略**：鼓励用户定期生成新的API密钥，减少长期密钥暴露的风险。
3. **限制密钥作用域**：利用`scope`字段定义最小权限原则，确保密钥只能访问必要的资源。
4. **监控异常活动**：检测短时间内大量API请求，可能表明密钥泄露或滥用。

### 潜在风险点

1. **明文密钥遗留**：尽管`secret`字段已被废弃，但仍需确保所有旧密钥都已成功迁移至哈希存储，避免明文密钥的长期存在。
2. **哈希碰撞风险**：虽然SHA-256的碰撞概率极低，但在极端情况下仍需考虑哈希冲突的可能性。
3. **密钥生成强度**：依赖`randomString`函数生成38位随机字符串，需确保随机数生成器的密码学安全性。
4. **迁移过程中的服务中断**：批量哈希化脚本在执行期间可能对数据库性能产生影响，需在低峰时段执行并监控系统状态。
