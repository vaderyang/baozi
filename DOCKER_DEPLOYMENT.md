# Docker Deployment Guide

This guide explains how to deploy Outline using Docker Compose for production.

## Overview

The Docker Compose configuration includes:
- **Outline App**: The main application server
- **PostgreSQL**: Database (version 16-alpine)
- **Redis**: Cache and session storage (version 7-alpine)

All services are connected via a dedicated Docker network with health checks and persistent volumes.

## Prerequisites

- Docker Engine 20.10+
- Docker Compose 2.0+
- At least 4GB RAM available for Docker
- Basic understanding of environment variables and OAuth configuration

## Quick Start

### 1. Configure Environment Variables

**Option A: Automated Setup (Recommended)**

Run the automated setup script:

```bash
./prepare-production.sh
```

This interactive script will:
- Generate secure random keys (SECRET_KEY, UTILS_SECRET, POSTGRES_PASSWORD)
- Prompt for your URL and port configuration
- Guide you through authentication provider setup
- Create a production-ready `.env` file
- Set secure file permissions (600)

**Option B: Manual Setup**

Copy the example environment file:

```bash
cp .env.production.example .env
```

Edit `.env` and configure **at minimum**:

```bash
# Required: Generate secure random keys
SECRET_KEY=$(openssl rand -hex 32)
UTILS_SECRET=$(openssl rand -hex 32)

# Required: Your public URL (default port is 6700)
URL=http://localhost:6700

# Port (default: 6700)
PORT=6700

# Required: Database credentials
POSTGRES_USER=outline
POSTGRES_PASSWORD=$(openssl rand -hex 32)
POSTGRES_DB=outline

# SSL/HTTPS (disabled by default, enable if not using reverse proxy)
FORCE_HTTPS=false

# Required: At least one authentication provider
# Example for Google OAuth:
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
```

### 2. Build and Start Services

```bash
# Build the application image
docker-compose build

# Start all services in detached mode
docker-compose up -d
```

This will:
1. Start PostgreSQL and wait for it to be healthy
2. Start Redis and wait for it to be healthy
3. Build the Outline application (if not already built)
4. Run database migrations automatically
5. Start the Outline application server

### 3. Check Service Status

```bash
# View running containers
docker-compose ps

# View application logs
docker-compose logs -f outline

# View all service logs
docker-compose logs -f
```

### 4. Access Your Instance

Once all services are healthy, access Outline at:
- `http://localhost:6700` (local, default port)
- Your configured `URL` (production)

## Production Deployment

### Using a Reverse Proxy (Recommended)

For production, use Nginx or Caddy as a reverse proxy:

**Nginx example:**

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        return 301 https://$server_name$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://localhost:6700;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**Caddy example:**

```
your-domain.com {
    reverse_proxy localhost:6700
}
```

### Environment Variable Configuration

Key environment variables to configure:

| Variable | Description | Required | Default |
|----------|-------------|----------|---------|
| `URL` | Public URL of your instance | Yes | `http://localhost:6700` |
| `PORT` | Port number for the application | No | `6700` |
| `SECRET_KEY` | Secret key for sessions | Yes | Generated by script |
| `UTILS_SECRET` | Secret key for utilities | Yes | Generated by script |
| `FORCE_HTTPS` | Auto-redirect to HTTPS | No | `false` |
| `DATABASE_URL` | PostgreSQL connection string | Auto-configured | - |
| `REDIS_URL` | Redis connection string | Auto-configured | - |
| Authentication provider credentials | OAuth credentials | At least one | - |

See `.env.production.example` for complete list.

### Production Setup Script

The `prepare-production.sh` script automates environment configuration:

**Features:**
- Generates cryptographically secure random keys
- Interactive prompts for configuration
- Validates required settings
- Sets secure file permissions
- Backs up existing .env files
- Supports multiple authentication providers

**Usage:**

```bash
# Make script executable (if needed)
chmod +x prepare-production.sh

# Run the interactive setup
./prepare-production.sh
```

The script will guide you through:
1. Generating secure secrets (SECRET_KEY, UTILS_SECRET, POSTGRES_PASSWORD)
2. Configuring your public URL and port
3. Selecting and configuring an authentication provider
4. Creating a production-ready .env file

**Script Output:**
- Creates `.env` with secure permissions (600)
- Backs up existing .env files with timestamp
- Provides configuration summary and next steps
- Validates all required settings

### OAuth Provider Setup

You need at least one OAuth provider. Popular options:

**Google OAuth:**
1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project or select existing
3. Enable Google+ API
4. Create OAuth 2.0 credentials
5. Add authorized redirect URI: `https://your-domain.com/auth/google.callback`
6. Copy Client ID and Secret to `.env`

**Slack OAuth:**
1. Go to [Slack API](https://api.slack.com/apps)
2. Create new app
3. Configure OAuth & Permissions
4. Add redirect URL: `https://your-domain.com/auth/slack.callback`
5. Copy credentials to `.env`

## Docker Compose Commands

### Starting Services

```bash
# Start all services
docker-compose up -d

# Start specific service
docker-compose up -d outline

# Start without detached mode (see logs)
docker-compose up
```

### Stopping Services

```bash
# Stop all services
docker-compose down

# Stop and remove volumes (⚠️ deletes all data)
docker-compose down -v
```

### Managing Services

```bash
# Restart a service
docker-compose restart outline

# Rebuild application after code changes
docker-compose build outline
docker-compose up -d outline

# View logs
docker-compose logs -f outline
docker-compose logs -f postgres
docker-compose logs -f redis
```

### Database Operations

```bash
# Run database migrations
docker-compose exec outline yarn db:migrate

# Access PostgreSQL shell
docker-compose exec postgres psql -U outline -d outline

# Create database backup
docker-compose exec postgres pg_dump -U outline outline > backup.sql

# Restore database backup
cat backup.sql | docker-compose exec -T postgres psql -U outline outline
```

## Data Persistence

Data is persisted in named Docker volumes:

- `postgres-data`: PostgreSQL database files
- `redis-data`: Redis persistence files
- `outline-data`: Uploaded files and attachments (when using local storage)

### Backup Data Volumes

```bash
# Backup PostgreSQL data
docker run --rm -v outline_postgres-data:/data -v $(pwd):/backup alpine tar czf /backup/postgres-backup.tar.gz -C /data .

# Backup Outline data (uploads)
docker run --rm -v outline_outline-data:/data -v $(pwd):/backup alpine tar czf /backup/outline-data-backup.tar.gz -C /data .
```

### Restore Data Volumes

```bash
# Restore PostgreSQL data
docker run --rm -v outline_postgres-data:/data -v $(pwd):/backup alpine tar xzf /backup/postgres-backup.tar.gz -C /data

# Restore Outline data
docker run --rm -v outline_outline-data:/data -v $(pwd):/backup alpine tar xzf /backup/outline-data-backup.tar.gz -C /data
```

## Scaling & Performance

### Horizontal Scaling

To run multiple Outline instances:

```bash
# Scale to 3 instances
docker-compose up -d --scale outline=3
```

Note: You'll need a load balancer (Nginx/HAProxy) to distribute traffic.

### Resource Limits

Add resource limits to `docker-compose.yml`:

```yaml
services:
  outline:
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 2G
        reservations:
          cpus: '1'
          memory: 1G
```

## Troubleshooting

### Container won't start

```bash
# Check container logs
docker-compose logs outline

# Check if dependencies are healthy
docker-compose ps
```

### Database connection errors

```bash
# Verify PostgreSQL is running
docker-compose exec postgres pg_isready

# Check database credentials
docker-compose exec outline env | grep DATABASE
```

### Permission errors with volumes

```bash
# Fix permissions on data directory
docker-compose exec outline chown -R nodejs:nodejs /var/lib/outline/data
```

### Reset everything (⚠️ destroys all data)

```bash
docker-compose down -v
docker-compose build --no-cache
docker-compose up -d
```

## Upgrading

To upgrade to a new version:

```bash
# Pull latest code
git pull

# Rebuild images
docker-compose build --no-cache

# Stop services
docker-compose down

# Start with new images
docker-compose up -d

# Run any new migrations
docker-compose exec outline yarn db:migrate
```

## Security Considerations

1. **Use strong secrets**: Generate with `openssl rand -hex 32`
2. **Enable HTTPS**: Use a reverse proxy with SSL/TLS
3. **Firewall**: Only expose necessary ports (80, 443)
4. **Regular updates**: Keep Docker images and dependencies updated
5. **Backup regularly**: Automate database and volume backups
6. **Use .env file**: Never commit secrets to version control
7. **Network isolation**: Services communicate only via Docker network
