## 简介
本文档详细阐述了用户与团队成员关系管理的API设计与实现。系统通过`UserMembership`模型管理用户对文档和集合的访问权限，支持成员的添加、移除、角色变更和批量操作等核心功能。文档将深入解析`userMemberships.ts`中定义的端点，包括邀请成员、接受邀请、更改角色和批量导入等操作的请求参数、响应格式及错误码，并结合`UserMembership`、`User`和`Team`模型解释其数据结构与关联关系。

## 成员状态机与权限模型

### 成员状态机
系统中的成员状态由多个因素共同决定，形成了一个复杂的状态机。核心状态包括：

- **active (活跃)**: 用户已登录并活跃使用系统。
- **pending (待定)**: 用户已收到邀请但尚未接受。
- **suspended (已暂停)**: 用户账户已被管理员暂停。

成员的最终状态是`User`模型和`Team`模型状态的综合体现。例如，当`User`的`suspendedAt`字段不为空，或其所属`Team`的`suspendedAt`字段不为空时，该成员即处于`suspended`状态。

```mermaid

[*] --> active
active --> pending : "收到邀请"
active --> suspended : "被管理员暂停"
pending --> active : "接受邀请"
suspended --> active : "被管理员恢复"
```

### 权限继承机制
权限继承是系统的核心特性之一。当一个文档被共享时，其子文档会自动继承父文档的访问权限。这一机制通过`UserMembership`模型的`sourceId`字段实现。

- **根成员关系 (Root Membership)**: 直接在文档上创建的成员关系。
- **派生成员关系 (Sourced Membership)**: 通过`sourceId`指向根成员关系的成员关系。

当根成员关系的权限发生变化时，所有派生成员关系会自动更新，确保权限的一致性。

## API端点详解

### 列出用户成员关系
此端点用于获取当前用户的所有成员关系。

```mermaid
sequenceDiagram
participant Client
participant API
participant UserMembership
Client->>API : POST /userMemberships.list
API->>UserMembership : findAll()
UserMembership-->>API : 返回成员关系列表
API->>Client : 返回分页数据和策略
```

**请求参数**
- `id` (string): 成员关系ID。
- `index` (string): 排序索引。

**响应格式**
```json
{
  "pagination": { ... },
  "data": {
    "memberships": [...],
    "documents": [...]
  },
  "policies": [...]
}
```

**错误码**
- `401 Unauthorized`: 用户未认证。
- `403 Forbidden`: 用户无权访问。

### 更新成员关系
此端点用于更新成员关系的排序索引。

```mermaid
sequenceDiagram
participant Client
participant API
participant UserMembership
participant Event
Client->>API : POST /userMemberships.update
API->>UserMembership : findByPk(id)
UserMembership-->>API : 返回成员关系
API->>UserMembership : 更新index
UserMembership->>Event : 创建更新事件
Event-->>API : 事件创建成功
API-->>Client : 返回更新后的成员关系
```

**请求参数**
- `id` (string, required): 成员关系ID。
- `index` (string, required): 新的排序索引。

**响应格式**
```json
{
  "data": { ... },
  "policies": [...]
}
```

**错误码**
- `400 Bad Request`: 请求参数无效。
- `404 Not Found`: 成员关系不存在。

## 权限继承与通知机制

### 权限继承流程
当在文档上创建或更新成员关系时，系统会自动为所有子文档创建或更新相应的派生成员关系。

```mermaid
flowchart TD
A[创建/更新根成员关系] --> B{是根成员关系吗?}
B --> |是| C[查找所有子文档]
C --> D[为每个子文档创建派生成员关系]
D --> E[设置sourceId指向根成员关系]
B --> |否| F[忽略]
```

## 批量操作与异步任务

### 批量导入成员
批量操作通过异步任务处理，以避免长时间阻塞API请求。系统会将批量导入任务放入队列，由后台工作进程处理。

```mermaid
flowchart TD
A[客户端发起批量导入] --> B[API接收请求]
B --> C[验证数据]
C --> D[创建异步任务]
D --> E[将任务放入队列]
E --> F[返回任务ID]
F --> G[客户端轮询任务状态]
H[工作进程从队列取出任务] --> I[处理每个成员]
I --> J[创建成员关系]
J --> K[更新任务状态]
```
