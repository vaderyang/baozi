## 简介
本指南旨在为 baozi 项目的开发者提供全面的开发指导。内容涵盖开发环境配置、编码规范、贡献流程、TypeScript 和 Vite 配置、代码格式化、静态分析、国际化支持、测试策略和持续集成最佳实践。通过本指南，开发者可以快速上手项目开发，提高开发效率和代码质量。

## 开发环境配置
为了顺利进行 baozi 项目的开发，需要配置以下开发环境：

1. **Node.js**: 项目要求 Node.js 版本为 `>=20.12 <21 || 22`。建议使用 nvm (Node Version Manager) 来管理不同版本的 Node.js。
2. **Yarn**: 项目使用 Yarn 作为包管理工具。安装 Yarn 可以通过 `npm install -g yarn` 命令完成。
3. **Docker**: 项目依赖 PostgreSQL 和 Redis 数据库。推荐使用 Docker 来快速启动这些服务。可以通过 `docker-compose up -d redis postgres` 命令启动。
4. **环境变量**: 项目使用 `.env` 文件来管理环境变量。在项目根目录下创建 `.env` 文件，并根据 `.env.development` 示例填写必要的环境变量。

完成上述配置后，可以通过以下命令启动开发环境：
```bash
yarn install
yarn dev:watch
```

## TypeScript 配置
项目使用 TypeScript 进行类型检查和编译。TypeScript 配置文件位于项目根目录下的 `tsconfig.json`。以下是关键配置项的解释：

- **allowSyntheticDefaultImports**: 允许从没有默认导出的模块进行默认导入。
- **alwaysStrict**: 在所有模块中启用严格模式。
- **esModuleInterop**: 启用 ES 模块互操作性，允许从 CommonJS 模块中导入默认导出。
- **experimentalDecorators**: 启用实验性的装饰器语法。
- **emitDecoratorMetadata**: 启用装饰器元数据发射。
- **forceConsistentCasingInFileNames**: 强制文件名大小写一致性。
- **isolatedModules**: 将每个文件视为独立的模块。
- **baseUrl**: 设置模块解析的基准路径。
- **jsx**: 指定 JSX 代码的生成方式。
- **lib**: 指定编译过程中包含的库文件。
- **module**: 指定模块代码生成方式。
- **moduleResolution**: 指定模块解析策略。
- **noErrorTruncation**: 不截断错误信息。
- **noImplicitAny**: 在表达式和声明上有隐含的 `any` 类型时报错。
- **noImplicitOverride**: 在派生类中覆盖基类方法时需要显式标记。
- **noImplicitReturns**: 函数中所有代码路径都必须有返回值。
- **noImplicitThis**: 在 `this` 表达式具有 `any` 类型时报错。
- **sourceMap**: 生成 sourcemap 文件。
- **resolveJsonModule**: 允许导入 JSON 模块。
- **strictNullChecks**: 启用严格的 null 检查。
- **noEmit**: 不生成输出文件。
- **skipLibCheck**: 跳过对声明文件的类型检查。
- **ignoreDeprecations**: 忽略特定版本的弃用警告。
- **target**: 指定编译后的 JavaScript 目标版本。
- **paths**: 配置模块路径映射。

## 前端构建工具 (Vite)
项目使用 Vite 作为前端构建工具。Vite 配置文件位于项目根目录下的 `vite.config.ts`。以下是关键配置项的解释：

- **root**: 指定项目根目录。
- **publicDir**: 指定静态资源目录。
- **base**: 指定基础路径。
- **server**: 配置开发服务器。
  - **port**: 指定开发服务器端口。
  - **host**: 指定开发服务器主机。
  - **https**: 配置 HTTPS。
  - **allowedHosts**: 指定允许的主机列表。
  - **cors**: 启用 CORS。
  - **fs**: 配置文件系统访问。
- **plugins**: 配置插件。
  - **react**: 使用 React 插件。
  - **VitePWA**: 配置 PWA。
  - **webpackStats**: 生成 webpack 统计文件。
- **resolve**: 配置模块解析。
  - **alias**: 配置模块别名。
- **build**: 配置构建选项。
  - **outDir**: 指定输出目录。
  - **manifest**: 生成 manifest 文件。
  - **sourcemap**: 生成 sourcemap 文件。
  - **minify**: 指定压缩工具。
  - **assetsInlineLimit**: 防止资源内联。
  - **target**: 指定目标浏览器。
  - **reportCompressedSize**: 报告压缩后的文件大小。
  - **rollupOptions**: 配置 Rollup 选项。

## 国际化 (i18n) 支持
项目使用 i18next 进行国际化支持。相关配置文件如下：

- **i18next-parser.config.js**: i18next 解析器配置文件，位于项目根目录下。配置项包括：
  - **contextSeparator**: 上下文分隔符。
  - **createOldCatalogs**: 是否创建旧的目录文件。
  - **defaultNamespace**: 默认命名空间。
  - **defaultValue**: 默认值生成函数。
  - **indentation**: 目录文件的缩进。
  - **keepRemoved**: 是否保留已从代码中移除的键。
  - **keySeparator**: 键分隔符。
  - **lexers**: 词法分析器配置。
  - **lineEnding**: 行尾字符。
  - **namespaceSeparator**: 命名空间分隔符。
  - **output**: 输出文件路径。
  - **input**: 输入文件路径。
  - **sort**: 是否对目录进行排序。
  - **skipDefaultValues**: 是否忽略默认值。
  - **verbose**: 是否显示解析信息。
  - **failOnWarnings**: 是否在警告时失败。
  - **customValueTemplate**: 自定义值模板。
  - **i18nextOptions**: i18next 选项。

- **app/utils/i18n.ts**: 前端 i18n 初始化文件，位于 `app/utils` 目录下。主要功能包括：
  - **initI18n**: 初始化 i18n 实例，加载所有可用的翻译资源。

- **shared/i18n/index.ts**: 共享的 i18n 配置文件，位于 `shared/i18n` 目录下。主要功能包括：
  - **languageOptions**: 定义支持的语言选项。

## 贡献流程
为了确保代码质量和项目稳定性，贡献者需要遵循以下流程：

1. **讨论**: 在提交 Pull Request 之前，先在 GitHub Issues 中创建或评论相关问题，与核心团队讨论解决方案。
2. **分支**: 从 `main` 分支创建新的功能分支。
3. **编码**: 遵循项目的编码规范和最佳实践。
4. **测试**: 编写充分的测试用例，确保新功能的正确性和稳定性。
5. **提交**: 提交代码并创建 Pull Request。
6. **审查**: 核心团队成员会审查代码，提出修改意见。
7. **合并**: 代码通过审查后，会被合并到 `main` 分支。

## 高级技巧
### 调试方法
- **日志**: 在开发环境中，项目会输出简单的日志到控制台。可以通过设置 `DEBUG` 环境变量来启用更详细的日志输出。
- **调试器**: 使用 Node.js 调试器，可以在 `dev` 脚本中添加 `--inspect=0.0.0.0` 参数。

### 性能分析
- **性能监控**: 使用 DataDog 或其他性能监控工具，监控应用的性能指标。
- **优化**: 通过分析性能瓶颈，优化数据库查询、减少网络请求、优化前端渲染等。

### 代码优化
- **代码分割**: 使用 Vite 的代码分割功能，按需加载模块。
- **懒加载**: 对于不常用的组件，使用懒加载技术。
- **缓存**: 合理使用缓存机制，减少重复计算和网络请求。
