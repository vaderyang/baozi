## 验证规则分层结构
文档验证系统采用分层架构设计，包含两个主要层次：模型级验证和业务逻辑验证。模型级验证在数据持久化前进行，确保数据符合预定义的格式和约束。业务逻辑验证则在服务层执行，处理更复杂的业务规则和上下文相关的验证需求。

```mermaid

B --> C[模型级验证]
C --> D[业务逻辑验证]
D --> E[数据持久化]
E --> F[响应返回]
```

## 验证流程与执行顺序
文档验证流程遵循严格的执行顺序，确保每个验证步骤都能正确执行。流程从客户端请求开始，经过中间件验证、模型级验证，最后到业务逻辑验证。每个步骤都有明确的职责和错误处理机制。

```mermaid
sequenceDiagram
participant Client as "客户端"
participant Middleware as "验证中间件"
participant Model as "模型验证"
participant Service as "业务逻辑验证"
participant Database as "数据库"
Client->>Middleware : 发送请求
Middleware->>Middleware : 解析请求数据
Middleware->>Model : 调用模型验证
Model->>Model : 执行长度验证
Model->>Model : 执行格式验证
Model-->>Middleware : 返回验证结果
alt 验证失败
Middleware-->>Client : 返回错误响应
else 验证成功
Middleware->>Service : 调用业务逻辑验证
Service->>Service : 执行业务规则检查
Service-->>Middleware : 返回验证结果
alt 业务验证失败
Middleware-->>Client : 返回业务错误
else 业务验证成功
Middleware->>Database : 提交数据
Database-->>Middleware : 返回操作结果
Middleware-->>Client : 返回成功响应
end
end
```

## 错误处理与用户反馈
系统提供了完善的错误处理机制，确保用户能够及时了解验证失败的原因并进行相应调整。错误信息经过精心设计，既包含技术细节又易于理解，帮助用户快速定位和解决问题。

```mermaid
flowchart TD
Start([开始验证]) --> ValidateTitle["验证标题长度"]
ValidateTitle --> TitleValid{"标题有效?"}
TitleValid --> |否| ReturnTitleError["返回标题长度错误"]
TitleValid --> |是| ValidateContent["验证内容长度"]
ValidateContent --> ContentValid{"内容有效?"}
ContentValid --> |否| ReturnContentError["返回内容长度错误"]
ContentValid --> |是| ValidateFormat["验证格式规范"]
ValidateFormat --> FormatValid{"格式有效?"}
FormatValid --> |否| ReturnFormatError["返回格式错误"]
FormatValid --> |是| ReturnSuccess["返回成功响应"]
ReturnTitleError --> End([结束])
ReturnContentError --> End
ReturnFormatError --> End
ReturnSuccess --> End
```
